# Phase 0 — task notes

## Dependency justifications (no new deps outside the pinned stack)

All runtime dependencies are from AGENTS.md §2 (pinned stack) or the standard
shadcn/ui companion utilities it implies:

- `hono`, `@hono/node-server` — the pinned API layer and Node adapter.
- `zod` — the pinned validation layer; lives in `@jaweb/shared`.
- `@libsql/client`, `drizzle-orm`, `drizzle-kit` — the pinned DB/ORM toolchain.
- `pino` — the pinned structured logger.
- `react`, `react-dom`, `react-router`, `@tanstack/react-query` — the pinned SPA stack.
- `tailwindcss`, `@tailwindcss/vite` — the pinned styling toolchain.
- `@fontsource/*` — self-hosted fonts required by §11 (no external font CDN).
- `clsx`, `tailwind-merge`, `class-variance-authority`, `lucide-react` — the shadcn/ui
  component primitives' standard companions; used only to compose the Button primitive.
  shadcn primitives themselves are never forked.
- `dotenv` — loads `.env` into `process.env` before the zod env schema parses it.
- `concurrently`, `tsx`, `typescript`, `@biomejs/biome`, `vitest` — dev tooling from §2.

## Version deviations from the local environment

- The pinned React Router major is **7** (AGENTS §2), so `7.18.7` is used even though
  v8 is current. A major bump needs human sign-off.
- TypeScript is pinned to `5.9.3` (latest 5.x) rather than the current 7.x rewrite.
- The local sandbox runs Node 26; CI and the deployment target remain Node 22 per §2.
  Only stable Node APIs are used, so the code runs on both.

## Migration strategy

`packages/shared` and the DB schema have a single owner per phase. Phase 0 owns no
product tables (out of scope: "any product tables"), so the baseline is an **empty
custom migration generated by drizzle-kit**, not a hand-edited SQL file. Phase 1 will
generate the users/sessions migration from the schema it owns.

## Local sandbox limitations (CI is the referee)

- `@libsql/client` has no native binding for Android/Termux, so `tests/health.test.ts`
  cannot execute in this sandbox. The route logic was verified locally with a temporary
  mocked-DB test (7 assertions passed across health + contracts), then that shim was
  removed. CI runs the real in-memory libSQL test on Linux.
- esbuild's bundled Android binary fails under the sandbox's global `LD_PRELOAD`;
  drizzle-kit's baseline migration was generated with `env -u LD_PRELOAD` and
  `ESBUILD_BINARY_PATH` pointing at the matching platform binary. CI needs no workaround.
- Markdown files are excluded from Biome formatting so the operating manual's tables
  (which contain pipes inside code spans) are never mangled by `pnpm format`.
- The Vite dev proxy covers `/api` only. The `/fonts` proxy listed in AGENTS §4 is not
  needed because fonts are bundled locally by `@fontsource` (§11: no external font CDN).
- `pnpm dev` cannot boot the API in this sandbox for the same libSQL native-binding
  reason; on a Linux host it runs API :8787 + Vite :5173 as documented.
